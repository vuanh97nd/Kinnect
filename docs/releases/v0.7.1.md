# Kinnect 0.7.1 — Native Android startup hotfix

Fixes a startup failure in 0.7.0 caused by compact SVG arc flags copied directly into Android vector pathData. The settings icon is loaded by the first screen; invalid arc argument groups could throw during drawable inflation before the app became usable.

- Normalize each SVG argument, treating the two arc flags as individual 0/1 characters, before exporting Android vectors.
- Regenerate all 83 web-derived native icons without changing their intended geometry.
- Retain legacy-icon fallback if a drawable unexpectedly fails to inflate.
- Validate every path's Android command arity, flags and number format; verify the compiled APK contains the corrected paths.
- Exercise the paths with a checksum-pinned AndroidX PathParser on the host JVM. The 0.7.0 baseline reproduces 44 parse failures; all 178 paths pass after the fix. Drawing is stubbed, so this is parser validation, not an on-device launch/render test.

Build: versionName 0.7.1, versionCode 16, min API 26 / target API 35. Native Android Views only, no WebView. APK v2/v3 signatures verified. Same signing certificate as the published 0.7.0 testing APK: SHA-256 d8809c1e21f00ccf96984b37123d3d916d2e103bfa1dc2032043f47bb3b9988d. Install over 0.7.0; no uninstall is needed for signing compatibility. The older GitHub 0.6.1 signing mismatch remains separate.

The six native-design checks and Java policy tests pass. A physical Android device is still needed for a complete startup, rendering, camera and RTC smoke test.
